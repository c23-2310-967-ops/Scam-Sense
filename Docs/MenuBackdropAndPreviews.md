# Main Menu: Cinematic Room Backdrop and Room Previews

## What the player sees
- **Background:** a loop of cinematic shots of the real rooms in 3D (no longer still screenshots), about a minute long:

  | # | Room | Shot |
  |---|---|---|
  | 1 | Level 1 | computer room establishing shot |
  | 2 | Level 1 | workstation close-up with the live "THREAT MONITOR" feed |
  | 3 | Level 2 | investigation office and its communications board |
  | 4 | Level 3 | operations room |
  | 5 | Level 4 | evidence wall detail |
  | 6 | Level 4 | forensics lab, wide |

  - Each shot is a slow, eased dolly, with a gentle sway and a little mouse parallax.
  - **Between shots** only the background dips briefly towards dark. The menu's Tint layer, behind all UI, darkens, so the camera can move to the next shot or room with no visible jump and never travels through furniture. The menu UI never fades or moves.
  - **Atmosphere:**
    - the server-rack LEDs blink and the corner monitor flickers;
    - a faint cyan glow falls from the workstation monitor;
    - very sparse dust drifts in front of the camera (about 60 unlit particles);
    - all feed entries are fictional `.example` domains.

### Adjusting the shots
- **Quick tweaks:** open `MenuBackdrop_Room1.unity`, select **MenuBackdrop**, and edit the **Shots** list. Each shot has:
  - a room index (0 = Level 1 … 3 = Level 4);
  - a start and end camera position;
  - a start and end look-at point;
  - a field of view and a duration in seconds.

  **Cut Seconds** sets the dip length; **Sway Amount** and **Parallax Degrees** set the subtle motion. Edits made this way are lost the next time the backdrop is rebuilt.
- **Permanent changes:** edit `Shots()` in `Assets/Editor/MenuBackdropBuilder.cs`, then run **Tools › Scam Sense › Menu › Build Menu Backdrop**.
- **Choosing an angle:** `LevelPreviewTools.Render(scenePath, new LevelPreviewTools.View(position, lookAt, fov), w, h, png)` renders a test frame of any room without changing it.
- **Main screen:** an *INVESTIGATION ROOMS · SNEAK PEEK* strip at the bottom right.
  - It shows a still of every room. Locked rooms are dimmed with a padlock, and the room to play next has a cyan outline and a CURRENT tag.
  - Clicking a room opens its preview.
- **Level Selection:** each card now has the room still.
  - It also shows LOCKED / CURRENT CASE / COMPLETED, the description and progress, plus **PREVIEW** and **PLAY**.
  - Locked rooms can be previewed, but PLAY stays disabled.
- **Room Preview panel:** a large still with the level number and name, its status, description, and unlock requirement or best score.
  - **PLAY** works only for unlocked rooms.
  - **‹ PREVIOUS / NEXT ›** browse the rooms.
  - **BACK** (or Esc) returns to wherever the preview was opened from.

The existing menu buttons (Play, Continue, Level Selection, Settings, How to Play, About, Quit) are unchanged.

## How it works
| Piece | File |
|---|---|
| Backdrop scene: copies of all four rooms (Level 1's house, Rooms 2-4) with the player, managers, screen UI, scripts, colliders and audio removed, each under a `Room_N` parent, plus the menu camera, shots, screen feed, monitor glow and dust | `Assets/Scenes/MenuBackdrop_Room1.unity`, generated by `Assets/Editor/MenuBackdropBuilder.cs` (**Tools › Scam Sense › Menu › Build Menu Backdrop**) |
| Shot loop, room switching with each room's own lighting, LED blink, screen feed | `Assets/Scripts/UI/MenuBackdrop.cs` |
| Room stills (1280×720 sprites) | `Assets/Art/LevelPreviews/level_N_preview.png`, made by `Assets/Editor/LevelPreviewTools.cs` (**Tools › Scam Sense › Menu › Capture Level Previews**) |
| Preview image per level | new optional field `previewImage` on `LevelDefinition` (set on all four level assets) |
| Strip, cards, preview panel, loading the backdrop, the background dip at cuts (Tint layer) | `Assets/Scripts/UI/MainMenuUI.cs` |

**Backdrop loading:**
- MainMenuUI loads `MenuBackdrop_Room1` additively when the menu opens and fades the old still shots out.
- While it's shown, the menu scene's camera and light pause, so exactly one camera renders. The menu's audio listener stays.
- Only the room in the current shot is switched on, so one room renders at a time. At each cut the backdrop applies that room's ambient lighting, and it puts everything back when it's disabled.
- Levels load as single scenes, so the backdrop unloads by itself.
- If the backdrop scene is missing or not in Build Settings, the menu simply keeps the still shots.

**Previews are pre-rendered stills of the actual rooms.** The menu never loads Rooms 2–4, so there's no extra memory or loading cost. A level without an image shows a "ROOM n · Preview not available" placeholder.

**Progression:** everything reads the existing `LevelCatalog.IsUnlocked` and `LocalDataManager`.
- Unlocks show up as soon as progress is refreshed.
- Previewing never writes to the save.
- `LoadLevel` still refuses locked rooms, so a preview can't bypass unlocking.

## After changing a room
- **Any room changed:** run **Build Menu Backdrop** to refresh the background. Close the level scenes in the editor first; the tool says so if one is open.
- **Any room changed:** run **Capture Level Previews**.

Both tools open the source scenes additively, never save them, and leave whatever scene you have open untouched. Camera angles are set in the two tools (`Shots()` / `Views`).

## Setup
Nothing to assign by hand. `MenuBackdrop_Room1` was added to Build Settings (after Room 4). The Menu scene itself wasn't modified: the strip and preview panel are built at runtime, like the Reset Progress panels.

## Limitations
- **Cost:** one room renders at a time with its own realtime lights, about the cost of standing in that room. All four room copies stay in memory while the menu is open (low-poly; the scene file is about 4 MB). It wasn't profiled separately.
- **Aspect ratios:** checked only in the Editor's Game view (16:9-ish and very wide). It wasn't checked on other monitors or in a built player.
- **Hand-picked views:** the shot positions and the Level 1 screen position come from each room's current layout. Moving furniture means checking the shots in `MenuBackdropBuilder`.
- **Effects:** there's no bloom or depth of field, because the project has no post-processing package and adding one wasn't worth it for a menu. The cool look comes from the rooms' own lighting, the cyan monitor glow and the menu's tint.
